# V1 General Audit — 2026-08-22

## Repository state
- Repository is public and default branch is `main`.
- No production secrets belong in the repository.
- V1 remains single-tenant and single-WhatsApp.

## Architecture reviewed
- SDR/state machine and decision contracts.
- Meta webhook/security adapter.
- Supabase persistence boundary.
- AI provider secret guard.
- Attribution and canonical acquisition sources, including LinkedIn.
- Lead scoring and routing.
- CRM projection and tenant isolation.
- HTTP health/webhook server boundary.
- Commercial licensing/entitlements kept outside V1 runtime policy.

## Release blockers
1. Configure fresh secrets in deployment environment, including a newly rotated OpenAI key.
2. Deploy backend behind public HTTPS.
3. Configure Meta webhook verification/callback for the single V1 WhatsApp number.
4. Connect real Supabase and verify persistence.
5. Execute end-to-end pilot matrix: text, media/audio, retries, duplicate events, context, failure and rollback.
6. Build/activate the owner-facing CRM UI after backend API contract is validated.

## Security findings
- Never place OpenAI, Meta, Supabase service-role or license-signing secrets in GitHub or browser code.
- The repository being public makes secret hygiene a hard release gate.
- The previously exposed OpenAI credential must not be reused.

## Scope discipline
Do not activate additional WhatsApp numbers or commercial billing enforcement before V1 passes its real release gate. LinkedIn is included as an acquisition source; advanced LinkedIn automation remains a later phase and must use permitted integrations.
